# MVP food-data availability audit

**Research date:** 2026-08-21  
**Question:** Which currently available data sources can support a Khmer-first packaged-food transparency MVP in Cambodia?

## Decision

Build the MVP around **sealed, retail packaged food and non-alcoholic beverages sold in Cambodia**, but treat Open Food Facts (OFF) as a barcode-indexed lead and evidence source—not as an authoritative or complete product registry.

The first useful product result should be:

1. an OFF barcode match and front image, when available;
2. the original ingredient/allergen evidence, when present;
3. a Khmer translation and conservative rules-based assessment generated by this project;
4. a guided label-photo flow whenever the evidence is absent, stale, conflicting, or does not match the physical package.

For MVP, explicitly decline to assess alcohol, dietary supplements, infant formula/specialized nutrition, medicines, restaurant/fresh food, and unlabeled products. OFF contains at least some alcohol, supplement, and infant-formula records under the Cambodia country tag, so being “in OFF” cannot itself establish that a product is in scope.

Do **not** ship any of the following claims from these sources alone: “safe,” “allergen-free,” “Halal,” “illegal,” “Cambodia-compliant,” or “made in country X.”

## Open Food Facts audit

### Capabilities and constraints

OFF describes itself as a collaborative database of food products with ingredients, allergens, nutrition facts, and label data. Its API documentation explicitly warns that data is supplied voluntarily and carries **no assurance of accuracy, completeness, or reliability**. The current read API is v3.6; structured multi-product search remains on deprecated v2, while v3 is under active development. The product schema includes product names by language, the main packaging language, countries where the product is sold, ingredient and nutrition structures, selected images, and structured packaging components. OFF also publishes multilingual taxonomies that normalize categories, labels, ingredients and packaging terms. Sources: [OFF API introduction](https://openfoodfacts.github.io/openfoodfacts-server/api/), [product schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product/), [product-tag schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_tags/), [taxonomy display API](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/taxonomy/get-api-v3-taxonomy-display-tags/), and [schema change log](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/ref-api-and-product-schema-change-log/).

The `countries` field is defined as the list of countries where a product is sold; it is not manufacture origin. The main `lang` field is intended to represent the predominant packaging language. Both are contributor-maintained product attributes, so Cambodia and Khmer facets are useful discovery filters, not verified market censuses. [OFF product-tag schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_tags/) and [product schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product/).

For small numbers of products, OFF provides image URLs for front, ingredients, nutrition and packaging selections. For larger image use, OFF recommends its AWS image dataset, which is synchronized monthly and can therefore lag the live service. [OFF image download documentation](https://openfoodfacts.github.io/openfoodfacts-server/api/how-to-download-images/) and [AWS images dataset](https://openfoodfacts.github.io/openfoodfacts-server/api/aws-images-dataset/).

For bulk analysis, OFF asks consumers retrieving more than a few hundred products to use its CSV or JSONL dumps. The official Python SDK documents CSV and JSONL product datasets. [OFF API introduction](https://openfoodfacts.github.io/openfoodfacts-server/api/) and [official SDK dataset documentation](https://openfoodfacts.github.io/openfoodfacts-python/usage/).

### Cambodia snapshot

I queried the official structured search endpoint with `countries_tags_en=cambodia` on 2026-08-21. It reported **1,231** matching records and returned **1,230** records in the unlimited-page response; this one-record discrepancy is a reminder that the live collaborative database is mutable and not a transactionally frozen census. [Reproducible OFF Cambodia query](https://world.openfoodfacts.org/api/v2/search?countries_tags_en=cambodia&page_size=0&sort_by=nothing&fields=code,product_name,product_name_km,lang,languages_tags,countries_tags,selected_images,ingredients_text,ingredients_text_km,allergens_tags,traces_tags,nutriments,quantity,brands,categories_tags,packagings,packagings_complete,complete,completeness,last_modified_t).

Field presence among the 1,230 returned records:

| Field/evidence              | Records | Share |
| --------------------------- | ------: | ----: |
| Product name                |   1,085 | 88.2% |
| Selected front image        |   1,059 | 86.1% |
| Any ingredient text         |     238 | 19.3% |
| Non-empty allergen tag list |     122 |  9.9% |
| Non-empty trace tag list    |      10 |  0.8% |
| Non-empty nutrition object  |     343 | 27.9% |
| Brand                       |     426 | 34.6% |
| Category                    |     291 | 23.7% |
| Structured packaging data   |     128 | 10.4% |
| Khmer product name          |      53 |  4.3% |
| Khmer language tag          |      68 |  5.5% |
| Khmer ingredient text       |       6 |  0.5% |
| OFF `complete == 1`         |       1 |  0.1% |

The mean OFF `completeness` value was approximately **0.306**. A separate image-metadata response showed selected ingredient-image keys for 189 records (15.4%) and nutrition-image keys for 196 (15.9%). Treat these two values as **lower bounds**, because OFF's search response exposed inconsistent legacy `images` and derived `selected_images` coverage; product-by-product reads are the reliable way to retrieve current selected image URLs. [Reproducible image-metadata query](https://world.openfoodfacts.org/api/v2/search?countries_tags_en=cambodia&page_size=0&sort_by=nothing&fields=code,images) and [OFF image-field documentation](https://openfoodfacts.github.io/openfoodfacts-server/api/how-to-download-images/).

These percentages measure **field presence**, not correctness. In particular, a non-empty allergen list is not proof of a complete allergen assessment, and an empty list must never be displayed as “none.” Khmer coverage is far too sparse for OFF alone to deliver the promised Khmer-first experience.

### Licensing

OFF states that the database is under the Open Database License, individual contents under the Database Contents License, and product images under CC BY-SA. It also warns that product images can contain third-party graphical elements subject to other rights. An MVP that caches or combines substantial OFF data needs an attribution, source-link, update and share-alike design reviewed before launch; images need attribution/source handling as well. [OFF licensing documentation](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/).

### Scope consequence

OFF is a strong fit for **barcode-first packaged-food discovery**, but its Cambodia subset is not remotely complete enough to power ingredient, allergy, nutrition or Khmer results without package capture and local enrichment. Its product-type boundary separates food, beauty, pet food and general products, but food categories still include higher-risk subclasses. The Cambodia snapshot included tagged alcoholic beverages, dietary supplements and infant formula. These must be denied or routed to a later specialist flow rather than analyzed by generic MVP rules. [OFF product read API product types](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/) and [product category schema](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_tags/).

## Allergen sources

The current Codex **General Standard for the Labelling of Pre-packaged Foods (CXS 1-1985, modified 2024)** identifies foods/ingredients that must always be declared with specified names when intentionally present. It is a defensible international seed for the canonical allergen table and label-declaration rules. [Codex standards index](https://www.fao.org/fao-who-codexalimentarius/codex-texts/list-standards/en/) and [CXS 1-1985 official PDF](https://www.fao.org/fao-who-codexalimentarius/sh-proxy/fr/?lnk=1&url=https%3A%2F%2Fworkspace.fao.org%2Fsites%2Fcodex%2FStandards%2FCXS+1-1985%2FCXS_001e.pdf).

Codex texts are voluntary until translated into national law. Therefore the MVP needs a local, versioned table with at least:

- canonical allergen and ingredient IDs;
- multilingual label names and synonyms for Khmer, English, Thai, Vietnamese and Chinese;
- relationship type (`DECLARED_CONTAINS`, `DECLARED_MAY_CONTAIN`, or ingredient-derived);
- source standard, jurisdiction and effective dates;
- explicit exemptions and derivation rules;
- evidence coverage state (`COMPLETE_READABLE_LABEL`, `PARTIAL`, `UNREADABLE`, `NOT_ASSESSED`).

No authoritative Khmer-ready machine-readable allergen vocabulary was identified in this audit. That translation and synonym work is a required local dataset. Codex itself cautions that its texts only become enforceable through national legislation. [Codex texts overview](https://www.fao.org/fao-who-codexalimentarius/codex-texts/en/).

## Additive sources

The Codex **General Standard for Food Additives (CXS 192-1995) Online Database** is searchable by additive name, synonym, INS number, functional class and hierarchical food category, and gives adopted additive provisions and use conditions. Its food-category hierarchy is explicitly not intended for labelling, so the project must curate a mapping from a package/product category to the correct GSFA category before applying a provision. [GSFA home](https://www.fao.org/gsfaonline/index.html?lang=en), [additive index](https://www.fao.org/gsfaonline/additives/index.html), and [food-category index](https://www.fao.org/gsfaonline/foods/index.html?lang=en).

Use GSFA to seed a local versioned table; do not call the human-oriented website as the runtime decision engine. This audit did not identify a documented public GSFA API or bulk machine-readable release. The official site states that the current online data is updated through the 48th Codex Commission session (2025), so ingestion must record an edition and be rerunnable. [GSFA home](https://www.fao.org/gsfaonline/index.html?lang=en).

EFSA's OpenFoodTox 3.0 provides downloadable Excel and IUCLID data plus dashboards. It covers substance identifiers, structured hazard assessments, toxicological reference values and source EFSA outputs; as of its April 2026 release it reports 7,880 distinct substances and 19,452 toxicological reference values. This is useful for traceable scientific explainers, not for a red/green product verdict. EFSA also directs users to the European Commission database—not OpenFoodTox—for the EU list of authorized additives and conditions of use. [EFSA OpenFoodTox](https://www.efsa.europa.eu/en/data-report/chemical-hazards-database-openfoodtox) and [EFSA food additives topic](https://www.efsa.europa.eu/en/topics/topic/food-additives).

For MVP, an additive result should be limited to:

- additive identified from readable label text;
- known name/INS/E-number synonyms and technological function;
- neutral explainer with its cited source;
- a jurisdiction/category-specific restriction only when a curated rule clearly applies;
- `CONCENTRATION_UNKNOWN` whenever the rule depends on amount and the label provides none.

## Cambodian official data

Cambodia's National Trade Repository publishes the Cambodian food-labelling standard **CS 001:2000**. It applies to pre-packaged food, requires core label information, and says imported products should have acceptable Khmer writing/stickers accurately reflecting the original label. The Repository also publishes a current measure derived from the product-quality law requiring ingredients, composition, user guidance, manufacture date and expiry date in Khmer. [CS 001:2000 on the National Trade Repository](https://cambodiantr.gov.kh/en/document/?title=prakas-no-1045-isc-cs001-2000-labeling-of-food-product) and [current Khmer-labelling measure](https://cambodiantr.gov.kh/en/measure/page/228/?title=labeling-requirement-placed-on-goods-including-imported-goods-circulating-in-cambodia-for-safety-and-health-purposes).

The CCF publishes a document library containing food-related Prakas, including prohibited chemicals, nutrition information requirements and Cambodia Halal certification procedure. The official page is a document catalogue rather than a documented structured API. [CCF Prakas library](https://www.ccfdg.gov.kh/en/laws-regulations/prakas/).

The Institute of Standards of Cambodia/MISTI exposes a public **Product Registration System** that searches the registration number printed in the Cambodian registration mark. This is potentially valuable when a clear mark is photographed, but it is not a barcode lookup and this audit found no public bulk export or documented API. [MISTI Product Registration System](https://products.misti.gov.kh/) and [ISC licensing information](https://isc.gov.kh/en/services/Licenses).

The MISTI standards catalogue lists Cambodian standards, including food standards, but does not present a comprehensive machine-readable national additive/allergen ruleset. [MISTI standards catalogue](https://misti.gov.kh/standards).

**Unresolved:** authoritative consolidation and effective-date/legal-status review of Cambodian additive, allergen and current pre-packaged-food rules. These sources are publicly obtainable, but are fragmented across HTML pages and downloadable documents. A Cambodian food-law reviewer should approve the curated rule set before the app makes any compliance statement.

## Cambodia Halal data

The CCF Department of Halal says it acts as secretariat to the Commission for Examination of Halal Products in Cambodia and investigates technical-standard/certification violations and misuse or expiry of Halal labels. The CCF also publishes the application Prakas. [CCF Department of Halal](https://www.ccfdg.gov.kh/en/about-ccf/department-of-halal/) and [CCF Prakas library](https://www.ccfdg.gov.kh/en/laws-regulations/prakas/).

The reviewed English ingredient-screening release now records four source sets separately:

- Cambodian Joint Prakas No. 090 (2020), published by the Ministry of Commerce and Ministry of Economy and Finance through CCF/CHSC, with the reuse decision `PUBLIC_GOVERNMENT_STANDARD`;
- licensed OIC/SMIIC 1:2019, _General Requirements for Halal Food_, with the reuse decision `LICENSED_STANDARD`;
- licensed OIC/SMIIC 24:2020, _General Requirements for Halal Food Additives and other Halal Chemicals_, with the reuse decision `LICENSED_STANDARD`; and
- the project-authored, reviewer-approved English term pack from [Issue 67](https://github.com/internetOnion/life-goods/issues/67), with the reuse decision `PROJECT_AUTHORED`.

These sources are published as immutable Reference Dataset Version
`halal-ingredient-2026-reviewed-english-v1`, canonical SHA-256
`fa2b3088080e4d1e6938610d518880231ea4a4cc0b5ffee3bfbf1ce5ae795a78`. The release records
`cambodia-halal-reviewer@lifegoods.org` and `HALAL_DOMAIN_REVIEW`; deployment activation records
a separate project-maintainer approval and does not replace that qualified review identity.

This audit did **not** identify an official public, barcode-searchable or API-accessible Cambodia Halal certificate registry. That absence is not proof that no internal or request-based registry exists; data access should be confirmed directly with CCF/CHSC.

Until such access exists:

- a photographed logo can only yield `SEAL_OBSERVED_NOT_VERIFIED`;
- a submitted certificate must retain certificate number, holder, scoped products/sites, certifier, issue/expiry dates and source document;
- `CERTIFICATE_VERIFIED` requires a direct authoritative lookup or manual confirmation;
- ingredient screening remains separate and may say “No non-Halal ingredients detected in the readable Evidence checked,” never “Halal.”

The current backend release is narrower still: it evaluates readable English Open Food Facts
ingredient Evidence as `PARTIAL`. It may report an explicit prohibited mapping, a
source-ambiguous mapping, or that no mapped concern was detected in the checked text. It does not
use an Open Food Facts community Halal label Claim, create a positive whitelist or blanket
E-number verdict, observe a seal, verify a Certificate, or establish a Product-level Halal
conclusion. OCR, translation, registry integration, and shopper Package Capture remain outside
this release.

## GS1/barcode data

GS1 explicitly states that the GS1 prefix does **not** show country of origin and does not mean a product was manufactured in a particular country or by a particular manufacturer; it identifies the GS1 Member Organisation that allocated the number. [GS1 prefix country-of-origin answer](https://support.gs1.org/support/solutions/articles/43000734188-does-the-gs1-prefix-first-3-or-4-digits-of-the-ean-13-barcode-number-show-the-country-of-origin-) and [GS1 Company Prefix](https://www.gs1.org/standards/id-keys/company-prefix).

Verified by GS1 can look up GTIN, company/licence and some product identity data; GS1 says advanced API querying is available through member organisations. It does not authenticate the scanned physical package or formulation. [Verified by GS1](https://www.gs1.org/services/verified-by-gs1) and [GS1 verification guidance](https://support.gs1.org/support/solutions/articles/43000734070-how-do-i-check-if-a-gs1-gtin-is-valid-).

MVP behavior should therefore be:

- normalize the GTIN and verify its check digit locally;
- use OFF for the product candidate;
- optionally use Verified by GS1 for licence/identity checks if access terms permit;
- compare front/package evidence before accepting a match;
- store manufacture country only as a separate evidence-backed label claim;
- never use a prefix-to-country table as manufacture origin.

## Proposed MVP data stack

### Runtime/seeded external data

- OFF product-by-barcode reads, cached with source URL, retrieval time, OFF revision/last-modified time, source field and licence attribution.
- OFF selected label images, fetched only as needed and shown with attribution/source.
- MISTI registration-mark point lookup when a legible registration number is present.
- Verified by GS1 only if the project obtains suitable access and terms.

### Locally curated, versioned data

- Ingredient/additive/allergen canonical vocabulary and multilingual synonyms.
- Codex CXS 1 allergen-declaration rules.
- Codex GSFA additive names, INS identifiers, functions, food categories and provisions.
- Cambodian legal overlays, each with jurisdiction, citation, effective dates and review state.
- Halal ingredient-origin rules and ambiguity states, kept separate from certification.
- Khmer translations reviewed for consumer clarity and safety-critical wording.

### User-generated evidence

- Observed Package photos, barcode, capture time/location if consented, package languages and matched revision.
- Original transcription spans tied to image coordinates.
- Translations and derived assessments linked back to each span and rule version.
- Per-claim provenance, confidence/review state, conflicts and supersession—not a single product-level “verified” badge.

## MVP acceptance gates

Before the MVP can display an assessment rather than only product identity:

1. The physical front package must plausibly match the catalogue candidate.
2. The relevant label panel must be complete and readable, or the result must prominently say partial/unreadable.
3. Derived allergen and Halal-ingredient results must name exactly which readable text was checked.
4. Additive restrictions require a versioned rule plus a sufficiently specific product category; concentration-dependent rules remain unresolved without concentration.
5. Expiry/manufacture/lot dates belong only to the observed package or batch.
6. Cambodia-compliance and certificate claims remain off unless supported by an authoritative, reviewed source.

## Remaining gaps to resolve

- Whether CCF/CHSC can provide an authoritative Halal certificate registry, export, API or verification service.
- Whether MISTI offers a supported API or bulk product-registration dataset and what its reuse terms are.
- A legally reviewed, current consolidation of Cambodian food-additive, allergen, label and nutrition requirements.
- Khmer/Thai/Vietnamese/Chinese ingredient and allergen synonym coverage and review workflow.
- Actual shelf coverage: scan a stratified sample of products in Cambodian markets and compare it with OFF, because the OFF country facet is contributor-maintained and not a market census.
- OFF ODbL/CC BY-SA compliance design for a database that mixes OFF data with locally submitted observations.
- A defined package-revision matching policy so an older OFF formulation is not presented as the current physical label.
